# Tahakkuk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Tahakkuk page under Finans: one association-wide list of yetkili × Adet × Tutar rows, edited in place, guarded against overwriting someone else's save.

**Architecture:** The Taahhütler pieces become generic "amount rows" (schemas, totals, server yetkili check, editor). New `accrual` table + `GET/PUT /api/accruals` with a content-hash `version` checked under a table lock. The page reuses the details-page save bar pattern.

**Tech Stack:** Next.js 16, Hono RPC, Drizzle/Postgres, zod, react-hook-form, TanStack Query, vitest.

**Spec:** `docs/superpowers/specs/2026-11-13-accruals-design.md`

## Global Constraints

- UI Turkish: sidebar "Tahakkuk" (last under Finans, `/accruals`), card title "Tahakkuk", add button "Tahakkuk ekle", 409 message "Tahakkuk siz düzenlerken başka biri tarafından değiştirildi. Değişikliklerinizi not alıp sayfayı yenileyin.", success "Tahakkuk kaydedildi".
- Same row rules as Taahhütler (Adet 1…1.000.000, Tutar > 0, Aktif yetkili for new rows, Pasif kept, duplicates allowed, max 500 rows).
- Audit: entity type `accrual`, action `update`, one `{ label: "Tahakkuk", from, to }` change; none when unchanged.
- Additive migration only. Tests restore the dev list and remove their own `accrual` audit rows.
- `pnpm lint`, `pnpm exec tsc --noEmit` and the touched tests pass after every task.

## Review Focus

1. Two PUTs with the same starting `version`: the second gets 409 and changes nothing (test).
2. A Pasif yetkili already in the list survives a save (test).
3. After a save the page's `version` is the new one, so a second save from the same tab isn't refused.
4. A 409 keeps the user's edits on screen.
5. Proje Taahhütler keep working after the generic rename (existing tests).

### Task 2: Accrual table, API, yetkili delete

**Files:** `src/db/schema.ts` (+ migration), create `src/app/api/[[...route]]/accruals.ts` (+ test), mount in `app.ts`, `src/lib/audit.ts` / `audit-filters.ts` / `audit-labels.ts`, `representatives.ts` + `representative-records.ts` (+ tests), `delete-representative-button.tsx`, create `src/lib/zod-schemas/accrual.ts`, `src/lib/fetches/accrual.ts`.

**Interfaces (produces):**
- `accrualTable` (`accrual`): like `project_pledge` without `project_id`; checks `accrual_quantity_positive`, `accrual_amount_positive`; index on `position`, on `representative_id`.
- `GET /api/accruals` → `{ rows: { id, representativeId, representativeName, representativeActive, quantity, amount }[], version: string }`.
- `PUT /api/accruals` body `accrualBodySchema = { rows: amountRowsSchema, version: z.string() }` → 200 `{ version, message: "Tahakkuk kaydedildi" }`; 409 `{ error: <conflict message> }`; 400 `{ error, field: "rows.N.representativeId" }`.
- `version` = sha256 hex of JSON of `[representativeId, quantity, amount]` per row in order.
- GET yetkili adds `accrualCount`; `representativeRecordsText({ collections, pledges, accruals })` → e.g. "2 tahsilat, 3 taahhüt ve 1 tahakkuk"; unknown → "tahsilat, taahhüt veya tahakkuk".
- fetches: `getAccruals(options?)`, `saveAccruals(rows, version)` → new version.
